## Body



<div class="x2mdx-ref-badges">

  <span class="x2mdx-ref-badge x2mdx-ref-badge--neutral">application/json</span>

</div>






<ParamField body="migration_id" type="number" required>
OpenAPI type: <code>integer (int64)</code>.



The migration id for which to return the summary.






</ParamField>



<ParamField body="record_time" type="string" required>
OpenAPI type: <code>string (date-time)</code>.



The timestamp at which the contract set was active. This needs to be an exact timestamp, i.e., needs to correspond to a timestamp reported by `/v0/state/acs/snapshot-timestamp` if `record_time_match` is set to `exact` (which is the default). If `record_time_match` is set to `at_or_before`, this can be any timestamp, and the most recent snapshot at or before the given `record_time` will be returned.






</ParamField>



<ParamField body="record_time_match" type="string" default="exact">


How to match the record_time. &quot;exact&quot; requires the record_time to match exactly. &quot;at_or_before&quot; finds the most recent snapshot at or before the given record_time.


Allowed values: <code>exact</code>, <code>at_or_before</code>.





</ParamField>



<ParamField body="owner_party_ids" type="string[]" required>


The owners for which to compute the summary.



Minimum items: 1.




</ParamField>



<ParamField body="as_of_round" type="number">
OpenAPI type: <code>integer (int64)</code>.



Compute holding fees as of this round. Defaults to the earliest open mining round.






</ParamField>

<div class="x2mdx-ref-badges">

  <span class="x2mdx-ref-badge x2mdx-ref-badge--neutral">application/json</span>

</div>






<ResponseField name="record_time" type="string (date-time)" required>

The same `record_time` as in the request.






</ResponseField>



<ResponseField name="migration_id" type="integer (int64)" required>

The same `migration_id` as in the request.






</ResponseField>



<ResponseField name="computed_as_of_round" type="integer (int64)" required>

The same `as_of_round` as in the request, with the same default.






</ResponseField>



<ResponseField name="summaries" type="HoldingsSummary[]" required>





<Expandable title="child attributes">




<ResponseField name="party_id" type="string" required>

Owner party ID of the amulet. Guaranteed to be unique among `summaries`.






</ResponseField>



<ResponseField name="total_unlocked_coin" type="string" required>

Sum of unlocked amulet at time of reception, not counting holding fees deducted since.






</ResponseField>



<ResponseField name="total_locked_coin" type="string" required>

Sum of locked amulet at time of original amulet reception, not counting holding fees deducted since.






</ResponseField>



<ResponseField name="total_coin_holdings" type="string" required>

`total_unlocked_coin` + `total_locked_coin`.






</ResponseField>



<ResponseField name="accumulated_holding_fees_unlocked" type="string" required>

Sum of holding fees as of `computed_as_of_round` that apply to unlocked amulet.






</ResponseField>



<ResponseField name="accumulated_holding_fees_locked" type="string" required>

Sum of holding fees as of `computed_as_of_round` that apply to locked amulet, including fees applied since the amulet&#x27;s creation round.






</ResponseField>



<ResponseField name="accumulated_holding_fees_total" type="string" required>

Same as `accumulated_holding_fees_unlocked` + `accumulated_holding_fees_locked`.






</ResponseField>



<ResponseField name="total_available_coin" type="string" required>

Same as `total_unlocked_coin` - `accumulated_holding_fees_unlocked`.






</ResponseField>




</Expandable>


</ResponseField>
