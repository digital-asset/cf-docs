### `data Account`

A data type to represent an on-chain managed account,

For example a traditional accounting structure, or simply a delegation to
a provider to perform some services.

Constructors:

<span id="constr-splice-api-token-holdingv2-account-85680"></span>
- `Account`

<ResponseField name="owner" type="Optional Party">
The party that owns the account, which MUST be set for regular accounts.

`None` is reserved for special accounts managed by the instrument

admin. Special accounts are for example used to represent the source

account for mints and the target account for burns.
</ResponseField>

<ResponseField name="provider" type="Optional Party">
The provider of the account.

Account providers MUST have visibility on all asset movements

and holdings. Asset implementations are free to determine how

authorization for asset movements is split between providers and

owners. For example, providers MAY have to authorize all movements

requested by the owner.
</ResponseField>

<ResponseField name="id" type="Text">
Account number or similar.

Use the empty string ("") as the default account identifier.
</ResponseField>

### `data Lock`

Details of a lock.

Constructors:

<span id="constr-splice-api-token-holdingv2-lock-95297"></span>
- `Lock`

<ResponseField name="holders" type="[Party]">
Unique list of parties which are locking the contract.

(Represented as a list, as that has the better JSON encoding.)
</ResponseField>

<ResponseField name="expiresAt" type="Optional Time">
Absolute, inclusive deadline as of which the lock expires.
</ResponseField>

<ResponseField name="expiresAfter" type="Optional RelTime">
Duration after which the created lock expires. Measured relative

to the ledger time that the locked holding contract was created.

If both `expiresAt` and `expiresAfter` are set, the lock expires at

the earlier of the two times.
</ResponseField>

<ResponseField name="context" type="Optional Text">
Short, human-readable description of the context of the lock.

Used by wallets to enable users to understand the reason for the lock.

Note that the visibility of the content in this field might be wider

than the visibility of the contracts in the context. You should thus

carefully decide what information is safe to put in the lock context.
</ResponseField>
